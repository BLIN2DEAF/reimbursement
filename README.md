# 报销自动化

本项目在本机完成报销材料识别、分类重命名和用友 BIP 差旅费用报账单辅助填单。

## 当前流程

1. 上传 PDF 或 JPG/PNG/WebP 图片；扫描版 PDF 会先把首页转换为图片再交给小米 Mimo 识别。
2. 识别发票、审批单、补助单等材料并提取结构化信息。电子发票若仅提取到表头而缺少金额，会先使用本地兼容解析器补全字体文字；住宿项目以“天/晚”为单位且只有一项时，可从票面数量提取住宿天数。
   无法识别或提取的文件自动保留为“其他凭证”，保留原文件名，在确认页提示并于最后作为影像附件一并上传，不中断其余材料处理；这些文件不参与费用数据提取。
3. 在确认页核对报销事由、补助天数和金额。
4. 打开 BIP 并填写基本信息和出差补助；补助完成后不再修改补助表。
   补助图片按人员逐条识别，每条人数固定为 1，分别保留个人天数、伙食补助和市内交通补助（包括扣减及明确的零金额）。BIP 按“人员 × 补助类型”分别增行，摘要标明人员，不能把多人合计填入单个人的明细。
5. 机票和高铁票分别上传到“交通费用”，每批上传后先完成交通新增行的收款人账号，再进入下一批；发票禁止上传到“出差补贴”。
6. 住宿发票只上传到“住宿费用”，并完成新增行的人员级别、城市、日期、天数、人数和收款人账号；其他发票只上传到“其他费用”，并完成新增行的收款人账号。
7. 填写附件张数、勾选“是否合并支付”，只点击“保存”生成草稿；不会点击“保存提交”。
8. 草稿保存成功后，从当前单据点击“影像扫描”，通过“本地导入”分批上传审批单、补助单等非发票附件，完成导入确认和影像保存后再等待人工复核。

系统不会自动提交报销单。

## 启动

1. 安装 Node.js 20 或更高版本，并安装 Poppler、确保 `pdftoppm` 已加入 PATH（用于扫描 PDF 识别）。
2. 复制 `.env.example` 为 `.env`，填写自己的图片识别模型、BIP 账号、银行卡号和补助标准。
3. 复制 `fill-config.example.json` 为 `fill-config.json`，填写付款银行和资金预算项目。BIP 登录地址及发行版专用选项已内置；报账事由和行政区划从材料识别结果生成。
4. 运行 `start.bat`，或执行 `npm start`。
5. 打开 `http://127.0.0.1:8080`。

重复运行 `start.bat` 时，如果该端口上已经是报销自动化服务，脚本会直接打开现有页面，不会重复启动；如果端口被其他程序占用，脚本会停止并提示修改 `.env` 中的 `PORT`，不会自动结束其他程序。

服务默认只监听本机地址，避免包含身份证号、银行卡号和发票信息的材料暴露到局域网。不要提交 `.env`、`fill-config.json`、`sessions/`、`recordings/`、日志、浏览器数据或真实报销材料。

## 安全分享

不要直接压缩整个项目目录，因为其中可能有本地密钥、登录态、报销材料和 Git 历史。请运行：

```powershell
npm run package:share
```

命令会先把本机 `.env` 和 `fill-config.json` 中的敏感值与待分享源码逐项比对，再生成 `release/reimbursement-app-share.zip`。分享这个 ZIP，不要分享原项目目录。

接收者需要自行准备：

- 图片识别服务的 API 密钥、OpenAI 兼容接口地址和模型名；
- 自己的 BIP 用户名和密码；
- 自己的银行卡号、付款银行、预算项目和补助标准；
- Node.js 20+、Poppler，以及访问本单位 BIP 和图片识别服务所需的网络环境。

发行版固定使用当前 BIP 登录地址，以及“联动支付、交通费、伙食费、管理费用、发票间合并、境内差旅费、高速集团其他管理人员”等页面选项。如果接收者使用的不是同一套 BIP 页面，需要修改自动化代码，不能只改配置文件。

每位使用者都应复制两份示例配置并填写自己的信息。不要把原作者的 `.env`、`fill-config.json` 或 API 密钥转交给接收者。

## Windows 完全离线运行版

需要给全新 Windows 电脑提供“解压后无需安装运行组件”的版本时，在已经装好项目依赖、Playwright Chromium 和 Poppler 的发布电脑上运行：

```powershell
npm run package:offline
```

输出文件为 `release/reimbursement-app-offline-windows-x64.zip`，其中包含 Node.js、项目依赖、Playwright Chromium 和 Poppler。接收者完整解压后，先双击 `1-首次配置.bat` 填写十项个人信息，再双击 `2-启动系统.bat`。

“离线运行版”表示接收者不需要再安装或下载这些运行组件；实际识别和填单仍需访问模型 API、单位 BIP，以及单位要求的内网或 VPN。离线 ZIP 体积为数百 MB，不要把已经生成 `.env` 或 `fill-config.json` 的使用目录再次转发。

## 质量检查

```powershell
npm run check
```

可另外执行 `npm run check:mimo` 使用程序生成的虚拟表单验证图片识别链路。该命令会访问已配置的模型 API，但不会上传真实报销材料。

修改 BIP 填单流程后，可执行 `npm run check:bip-mapping`，在本地合成页面中验证发票费用分区、新增行定位、附件张数、合并支付、影像附件导入与保存，以及只点击“保存”而不点击“保存提交”的安全边界。该检查不会登录 BIP，也不会创建报销草稿。

该命令执行 TypeScript 编译检查和核心解析/文件整理测试。真实 BIP 页面会随系统升级变化，因此发布前还需要人工执行一次受控端到端验收。

## 端到端验收清单

- 登录、强制登录提示和表单导航正常。
- 报账事由、结算方式、付款账户和预算项目正确。
- 补助行的业务属性、类型、天数、人数、金额和收款账号正确。
- 所有发票都进入正确费用分区，上传数量与材料数量一致。
- 机票、高铁票、住宿和其他费用的新增行均已选中正确收款账号；住宿字段与审批单一致。
- 审批单、补助单等影像附件已保存，附件张数正确。
- 页面显示“填单完成”后，在 BIP 中人工核对并提交。
